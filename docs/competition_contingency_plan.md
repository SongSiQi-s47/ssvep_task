# 正式赛题分布变化的准确率储备路线（2026-10-28）

## 已知边界

书面赛题为八类逐试次分类，算法任务按全体试次 ACC 计分（60%），技术报告占 40%；要求填写赛方标准结果文件，并强调选手独立编程。旧版赛制文本说明正式数据解密后约四小时提交窗口，但具体赛程及格式须以本轮最终通知为准。直播答疑转写提到每类可能有一份带标签参考样本、片段可变长、可用完整片段、今年格式与旧 CSV 不同；参考样本归属范围与通道/刺激配置仍未定。

现有 v9 整段六通道三谐波 FBCCA 是无需训练的稳定默认。v10 后部电极五谐波在八名 BETA 开发被试上提高，却在五名新被试上下降 3.75 个百分点；不能依据小开发集挑更多谐波/电极，也不能把 D1/D2 近满分样例当正式泛化证据。D1/D2 继续只做验证，不做训练、校准或伪标签。

## 按条件启用的储备

| 触发情况 | 备用方法 | 使用条件与退出条件 |
|---|---|---|
| 元数据与旧样例一致，无明确同组支持样本 | v9 整段 FBCCA：以实际 fs 生成正余弦参考，核对六通道顺序和 0–7 频率映射 | 默认；若通道/频率/采样率变更，先修正元数据和适配器，不能静默按旧参数运行 |
| 赛方明确给每类一个带标签参考，且与待测属于同组/同人 | 一次一类的轻量模板相关与标准 FBCCA 分数融合；只用官方指定 support，query 不参与拟合 | 事前用 BETA 一 block 每类一例、其余 block 作为独立 query 验证；按被试统计相对 v9 的收益与损害，预先冻结融合规则。正式样本来后只执行已验证规则 |
| 支持样本与待测人的归属不明确或不一致 | 继续用解析 FBCCA；模板方法只作并列诊断，不用未知组别强行校准 | 不把不同人的模板当个人模板；先核对文件提供的组/被试标记 |
| 物理频率集合或标签顺序改变 | 按赛方刺激元信息重建八个参考频率；若仅有标注参考，先检查频谱峰、谐波和八类对应是否自洽 | 参考不足以可靠判定映射时，不凭 D1/D2 原顺序猜测；必要时以标注参考建立映射并留下不确定性记录 |
| 片段长度显著变短、起点有非刺激段、通道改变 | 对齐事件边界，在公开数据构造类似长度/缺失通道情形，做完整片段 FBCCA 与保守短窗对照 | 不补零冒充有效刺激；当公开隔离验证不能证明改动有益时维持原方案 |
| 新域与 BETA 的人员、设备或噪声差异大 | 用公开 Benchmark/BETA 按数据集及被试分别外部确认；已训练 EEGNet 仅保留候选 | 不根据 D1/D2 反复调参；不因外部数据总窗口数多就认为有更多独立被试 |

## 试验顺序

1. **先实现格式适配与元数据审计。** 记录原始文件 SHA256、受试者/组标识、任务 ID、采样率、通道名及顺序、物理频率与标签映射、开始/结束事件、长度、单位、缺失/非有限样本。输出内部统一的逐试次信号；校验任务数与原顺序，不使用类别出现次数做排列约束。
2. **优先验证一例每类的支持集方案。** 在公开 BETA 按被试分别取一个独立 block 的八条作为 support，其余 block 作为 query，轮换支持 block；严格禁止同一试次切窗跨 support/query。报告总体试次 ACC、每被试 ACC、最差被试、逐类错分和对 v9 的配对差异。再将整套规则冻结，在此前未参与选择的公开被试或另一数据集确认。单例模板易受噪声、相位、起点影响，默认保留解析 FBCCA 分支。文献中模板+CCA 的优势不能直接当本赛题一例/类的效果。
3. **做域偏移压力测试。** 用可得公开数据模拟错通道顺序、通道缺失、不同信号长度、起点变化、幅值单位变化、工频噪声；每类情形分别验证修复输入后是否恢复准确率。正式输入遇到未支持的元数据时清楚失败，不能默默输出八类结果。
4. **赛时四小时优先级。** 先读最新版格式说明和样例，做一次端到端输入/输出与标准 Excel 原文件名/行 ID 核对；运行 v9 保底；仅在官方参考支持集的组别、标签和经预验证的融合规则都满足时启用适配；最后核对记录总数、预测范围、文件结构和技术报告，不用未知答案做临场调参。

## 不宜作为当前主储备的方法

标准 TRCA 借助同一类别多次独立重复的时间锁定一致性来学习空间滤波；每类仅一条时不能把重叠窗口伪装成多次独立试次。复杂深度网络微调、自训练伪标签和按旧 D1/D2 继续挑参数，在小样本/域偏移下存在较大失败风险。若正式资料明确提供了更多独立带标签参考，再单独验证这些方法。

书面规则对外部自动化工具和第三方成品算法有严格措辞，直播转写对 AI 辅助的口头描述不同；提交前以组委会最新书面要求核对。仓库的公开数据下载与研究实验、最终由选手独立编程实现的提交物需明确区分。技术报告应诚实写出方法选型、失败实验、适配条件、数据来源、验证隔离和正式输入限制。
